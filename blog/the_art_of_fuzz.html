The Art of Fuzz: Closing the Semantic Gap with LibLMFuzz and SemTaint

Prabhav Srinath | May 2026 | Methodology & Architecture

TL;DR

Coverage-guided fuzzers know when they've hit a new branch. They have zero idea what that branch means. That disconnect — the "semantic gap" between low-level instruction execution and high-level developer intent — is where the deepest architectural security bugs hide. I've spent the past year building and refining two systems to close this gap: SemTaint (a multi-agent LLM framework that extracts intent-aware semantic taint specifications from stripped binaries) and LibLMFuzz (an agentic self-repairing fuzz driver generator with compiler diagnostic feedback). Together with targeted manual research, they powered the discovery of high-severity CVEs across CUPS, Netty, Jackson, and nginx.

The Bottleneck Was Never Execution Speed

Modern security auditing is a race between software complexity and human bandwidth. Tech stacks are taller than ever: enterprise orchestration engines, JIT polyglot runtimes, and high-throughput network event loops.

You cannot read code exponentially faster. The CUPS heap overflow (CVE-2026-34979), the Netty CONTINUATION flood (CVE-2026-33871), the nginx integer overflow (CVE-2026-27784), and the Jackson async bypass (GHSA-72hv-8253-57qq) were not accidental finds. They were systematically surfaced by shifting how we model code invariants and auditing where automated analysis flags anomalous patterns.

Three Eras of Fuzzing

  1. Era 1: "Dumb" Black-Box Fuzzing: Throw random bytes at stdin or sockets and listen for segfaults. Great for 1995 file parsers; useless for nested JSON or HTTP/2 frame streams.
  2. Era 2: Coverage-Guided Grey-Box Fuzzing (AFL, libFuzzer): Instrument basic blocks, track edge transitions, and prioritize seeds that increase code coverage. This was revolutionary, but it hit a hard ceiling: it is semantically blind. It knows a branch flipped; it doesn't know that flipping that branch dropped a security validation check.
  3. Era 3: Symbolic & Directed Fuzzing: Use SMT solvers (Z3) to solve constraints and force execution down deep paths. Powerful, but notoriously susceptible to state explosion and path explosion in large codebases.

Where LLMs Actually Matter (Beyond the Hype)

There's a lot of noise about "AI finding 0-days." LLMs cannot magically find bugs out of thin air. What LLMs excel at is the semantic translation layer: inferring developer intent from disassembly, variable naming, and API contracts.

1. SemTaint: Intent-Aware Taint Analysis

When you audit a stripped binary or a closed dynamic library, variable names and types are wiped out. Traditional Datalog taint engines track register flows (e.g. RAX → RDI), but they cannot answer: "Is this register supposed to be an upper bound or a current offset?"

SemTaint uses a multi-agent pipeline to reconstruct intent:

  • Decompilation Specialist: Analyzes control-flow graphs (Ghidra/IDA decompiler output).
  • Specification Agent: Assigns semantic roles to registers (e.g., [RSI+8] = user_controlled_length, [RDI+16] = allocated_capacity).
  • Differential Invariant Verifier: Compares sibling execution branches to flag dropped checks (how we spotted the missing validateIntegerLength() in Jackson's async path).

2. LibLMFuzz: The Agentic Self-Repairing Loop

Writing stable libFuzzer harnesses for black-box or stripped libraries is tedious. You need exact struct definitions, correct memory initialization, and proper API linkage.

LibLMFuzz automates this using an agentic feedback cycle: 

// The LibLMFuzz Agentic Repair Loop
1. Extract  Exported symbols and ABI conventions from binary headers / disassembly.
2. Generate Initial C/C++ libFuzzer harness with LLVMFuzzerTestOneInput.
3. Compile  Run clang with ASan/UBSan instrumentation and capture stderr diagnostics.
4. Self-Repair: Agent inspects compiler error + disassembly to resolve types:
             "Fixed incomplete type: inferred struct size 0x48 from memset in target."
5. Execute  Run fuzzer with corpus generation and coverage monitoring.

Real-World Battle-Tested Impact

Vulnerability How SemTaint & LibLMFuzz Cracked It
CUPS Heap Overflow (CVE-2026-34979) SemTaint identified the discrepancy where ipp_length() omitted IPP_TAG_URI during sizing while get_options() wrote it out. LibLMFuzz crafted valid IPP packets to trigger the heap overwrite.
Netty CONTINUATION Flood (CVE-2026-33871) Semantic analysis revealed that maxHeaderListSizeGoAway evaluated byte counts rather than frame transactions. LibLMFuzz generated streams of valid 0-byte frames to bypass byte guards.

Where Security Research Is Headed

We are transitioning from the era of manual harness crafting to the era of the Strategic Security Orchestrator. The researcher's role is shifting toward hypothesis formation, threat modeling, and differential analysis — asking the questions that automated tools are blind to.
