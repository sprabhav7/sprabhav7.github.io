CVE-2026-38964: Unsandboxed GraalVM Python Context in Conductor-OSS Leads to Remote Code Execution (RCE)

Vulnerability Research | June 5, 2026
CVSS 4.0 Score 9.3 (Critical)
CWE Identification CWE-94
CVSS Vector String CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N
CVE CVE-2026-38964
Affected Versions Conductor-OSS (All Versions)

Summary

I identified a critical security flaw in the PythonEvaluator component of Conductor-OSS, an open-source orchestration engine. This vulnerability allows any unauthenticated remote attacker to execute arbitrary OS commands on the server by leveraging an unsandboxed GraalVM Python context. Research revealed that a combination of unconditional evaluator enablement, a lack of API authentication, and over-privileged execution contexts makes stock deployments vulnerable out-of-the-box.

Impact

  1. Unauthenticated RCE: Any network-reachable client can trigger code execution without valid credentials or tokens.
  2. Full System Compromise: Payloads execute with the privileges of the Conductor-OSS process, enabling arbitrary file read/write and process execution.
  3. Internal Network Pivoting: A compromised server can be used as a beachhead to attack internal infrastructure that is otherwise shielded from the internet.

Description

Analysis shows the vulnerability arises from three intersecting architectural decisions in the Conductor-OSS framework.

1. Unsandboxed GraalVM Context

I discovered that in PythonEvaluator.java, the GraalVM Context is initialized with the allowAllAccess(true) flag. This "super-permission" explicitly disables all security sandboxing, granting the script host-level access to the filesystem, network, and system environment.

// core/.../evaluators/PythonEvaluator.java
try (Context context = Context.newBuilder("python")
    .allowAllAccess(true)
    .build()) {
    ...
}

2. Direct Execution of User Expressions

The INLINE system task facilitates the direct evaluation of logic provided in the workflow definition. When a task specifies evaluatorType: "python", the provided expression is wrapped in a Python function and executed. I found no validation or filtering performed on the expression string before it reaches the evaluator.

3. Default Unauthenticated REST API

Finally, I noted that Conductor-OSS does not implement authentication for its REST controllers by default. The MetadataResource and WorkflowResource endpoints are exposed, enabling a simple two-step exploitation chain: registering a malicious workflow and executing it synchronously to capture the command output directly in the HTTP response.

POST /api/metadata/workflow — Register workflow with INLINE python task
POST /api/workflow/execute/{name}/1 — Execute it synchronously
  → WorkflowResource.executeWorkflow()
    → Inline.execute()
      → evaluators.get("python") → PythonEvaluator.evaluate()
        → Context.newBuilder("python").allowAllAccess(true).build()
        → context.eval("python", wrappedExpression) ← ARBITRARY CODE RUNS HERE
  → result returned in HTTP response

Responsible Disclosure

I conducted this research following a multi-month effort to ensure coordinated disclosure across the project maintainers, GitHub, and MITRE.

  • February 19, 2026: Identified the vulnerability and reported it to the repository owners via a GitHub Security Advisory.
  • March 12, 2026: First follow-up communication after receiving no response.
  • March 29, 2026: Second follow-up communication.
  • March 30, 2026: Escalated the matter to MITRE for CVE assignment after receiving no acknowledgment from the maintainers.
  • June 5, 2026: CVE-2026-38964 was assigned and I published the findings following the expiration of the disclosure window.

Conclusion

This research highlights the severe risks of using powerful runtimes like GraalVM without strict sandboxing. By enabling allowAllAccess(true) in an environment that processes user-provided logic without authentication, Conductor-OSS created a direct path to total system compromise. Until an official patch is released, users are advised to ensure their instances are strictly internal and protected by robust network-level authentication.
